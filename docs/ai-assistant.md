# AI 站内助手：实现与技术路线

> 当前版本：检索增强（RAG）最小闭环，模型用智谱 GLM-4.7-Flash 免费档。

## 一、为什么不是「把 699 条题目全塞给模型」

699 条题目约 4 万字，全部塞进 prompt 有两个问题：每次调用 2 万+ token（免费档也会限流），
而且模型容易在长上下文里挑错题、编题号。所以采用检索增强：

```
用户提问
   ↓
① 本地检索（PHP，0 成本，几十毫秒）
   口语清洗 → 同义词映射 → 中文 2-gram + 型号词 → idf 加权打分
   命中 top 8 题目 + top 2 项目
   ↓
② 组装 prompt（约 900 token：系统规则 + 站点概况 + 8 条题目 + 2 个项目）
   ↓
③ 调 GLM-4.7-Flash 生成回答（带 [1] [P1] 引用标号）
   ↓
④ 前端渲染回答 + 下方列出可点击的来源卡片
```

关键点：**模型只负责组织语言，不负责找题**。它看到的 8 条就是全部事实来源，
所以不会出现「编一个不存在的题目」这种情况；真没有相关内容时会明说「站内暂时没有」。

## 三、配置步骤（5 分钟）

1. 打开 <https://open.bigmodel.cn/usercenter/apikeys>，登录后创建 API Key（形如 `xxxxxxxx.yyyyyyyy`）。
2. 进后台 `https://www.lk-mcu.online/admin.html` → 左侧「AI 助手」。
3. 粘贴 Key，模型填 `glm-4.7-flash`，点「测试连接」——成功会显示 `连接成功 · glm-4.7-flash · 800ms`。
4. 勾选「在网站上显示助手入口」→ 保存配置。
5. 打开首页，右下角出现「问选题」，点开问一句试试。

Key 存在服务器 `data/ai-config.php`，内容是 `<?php return [...];`，被浏览器直接访问时 PHP 只执行不输出，
和密码文件同一套保护。接口只返回掩码（`abcd********wxyz`）。

## 四、额度与成本

| 参数 | 默认值 | 位置 |
|---|---|---|
| 每人每日次数 | 30 | 后台「每人每日次数」 |
| 全站每日上限 | 800 | 后台「全站每日上限」 |
| 同一 IP 最小间隔 | 3 秒 | `api.php` → `AI_MIN_INTERVAL` |
| 单次问题长度 | 200 字 | `api.php` → `AI_MAX_QUESTION` |
| 答案上限 | 900 token | 后台可调（未暴露，改 `ai-config.php`） |
| 缓存 | 相同问题 7 天内直接复用 | `data/ai-cache.php`，最多 400 条 |

- GLM-4.7-Flash 是免费档，正常聊天的边际成本是 **0**。
- 如果哪天换成付费模型：一次对话约 1.3k token（900 输入 + 400 输出），
  按主流定价 1–2 元/百万 token 的量级估算，1 万次对话大约 20–40 元。
- 三层挡板：IP 日限 → 全站日限 → 缓存。被刷时最坏情况也能被全站上限截断。

## 五、体验上的设计取舍

1. **不做全屏聊天页**，做右下角悬浮面板：学生看题目时随口问一句，不需要离开当前页面。
2. **回答下面一定列来源卡片**：点「[2]」对应的卡片直接跳到选题页并自动搜索该题目，
   比让模型复述题目更有用——用户要的是「去那条题目」。
3. **预设问题**放在首次打开时：很多人不知道怎么问，给 4 个例句（器材、方向、项目原理、答辩）
   比空输入框有效得多。
4. **不存对话历史**：刷新即清空，避免在服务器落访客数据；不存 IP 明文，限流只存哈希。
5. **接口挂了不影响页面**：`ai_status` 失败时前端静默不渲染入口，主站功能完全不受影响。

## 六、技术路线：怎么把体验继续往上推

### 第 1 阶段（已完成）
检索增强 + 引用卡片 + 限流缓存 + 后台可视化配置。
验收标准：问 10 个真实问题，8 个能在 3 秒内给出可点击的题目。

### 第 2 阶段（1–2 周，性价比最高）
1. **流式输出**：SSE 边生成边显示，首字时间从 2–3 秒降到 0.5 秒以内。
   用户对「等待」的感知主要取决于首字时间，这是最直接的一档体验提升。
2. **一键生成开题报告大纲**：在题目卡片旁加「生成大纲」，输出研究背景 / 方案 / 硬件选型 /
   进度安排，支持复制或导出 Markdown。这是学生真正愿意转发给同学的功能。
3. **结构化筛选**：把「我只有 51 单片机」这类条件做成表单（主控 / 预算 / 周期 / 是否需要 App），
   检索按条件过滤，比纯自然语言更准。
4. **反馈按钮**：每条回答下加「有用 / 没用」，埋点记录到 `data/ai-feedback.php`，
   用于后续调整检索权重——这是唯一能持续变好的信号来源。

### 第 3 阶段（1 个月）
1. **混合检索**：关键词（现状）+ 向量（硅基流动 `bge-m3` 免费）双路召回后融合排序。
   解决「同义词/近义表达」召回不足的问题，例如「帮老人看有没有摔倒」要能召回「跌倒检测」。
2. **相似题目归并**：699 条里存在大量同质题目（同一功能不同主控），聚类后只展示代表项 + 变体，
   减少「看起来都一样」的疲劳。
3. **答案沉淀成 SEO 页面**：把高频问题 + 回答生成静态 FAQ 页（「STM32 毕设题目怎么选」等），
   既省 token 又吃搜索流量——这是把 AI 成本转化为获客资产的关键一步。

### 第 4 阶段（季度）
1. 账号体系 + 收藏夹 + 我的选题进度（本地存储先做，量起来再上服务端）。
2. 方案生成：从题目 → 系统框图 → 元件清单（BOM）→ 关键代码骨架，形成「选题到最后交付」的闭环。
3. 分享链接：把某次问答生成只读链接，方便学生发给导师/同学，天然带传播。

### 衡量指标
| 指标 | 现状 | 目标 |
|---|---|---|
| 首字响应 | 2–3s（非流式） | < 0.5s（流式） |
| 答案带来源比例 | 100%（强制） | 保持 100% |
| 来源卡片点击率 | 待埋点 | > 25% |
| 追问率 | 待埋点 | > 30% |
| 单次对话成本 | 0 元（免费档） | 保持 0，量超限再换 |

## 七、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 右下角没有入口 | 后台未开启，或 Key 为空 | 后台「AI 助手」检查开关与 Key |
| 测试连接返回 401 | Key 错、过期、或不符 `xxxxxxxx.yyyyyyyy` 格式 | 重新生成 Key |
| 测试连接返回 404 | 模型名写错 | 换 `glm-4.7-flash` |
| 提示「今天的次数已用完」 | 触发 IP 日限 | 后台调大，或等次日 |
| 提示「data/ 目录不可写」 | 部署后属主不对 | 部署脚本已 chown `www:www`，手动执行 `chown -R www:www data && chmod -R 775 data` |
| 回答里全是「站内暂时没有」 | 检索没命中 | 换个带主控或功能词的问法；或扩充 `aiSynonyms()` |
| 报「服务器未启用 curl」 | PHP 缺 curl 扩展 | `apt install php-curl` 或宝塔「PHP 设置 → 安装扩展」 |
